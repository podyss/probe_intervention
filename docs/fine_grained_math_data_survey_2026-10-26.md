# 近期数学细粒度推理数据构造：2025 下半年—2026

调研日期：2026-10-26。按用户反馈，将重点改为 2025 下半年至今的方法；2023–2024 工作仅留作背景。日期尽量使用首次提交日期，不能将会议年份当成方法首次出现的年份。以下区分直接的数据构造方法、可用于构造数据的验证器，以及仅有推理时实验的方法。本文未运行复现实验，也未完整审计各论文代码与数据开放状态。

## A. 近期方法：先读这些

### A.1 CoRD：按步骤组合多个教师，用答案可预测性选择分支

**论文：Distilling Long-CoT Reasoning through Collaborative Step-wise Multi-Teacher Decoding，首次提交 2026-05-04。** [摘要与日期](https://arxiv.org/abs/2605.02290) · [方法 §4](https://arxiv.org/html/2605.02290v1)

同一个推理前缀下，让不同教师分别提出下一步；meta-prover 依据“加入这一步后，标准答案的条件概率”计算 predictive perplexity 分数；再用 beam search 保留多个候选前缀，逐步组合出用于蒸馏的 Long-CoT。作者同时比较了步骤划分、候选选择与搜索策略。

**与当前项目最接近的地方**是把前缀对答案预测的影响用于数据构造。区别在于：CoRD 主动生成和挑选候选下一步，当前仓库则在固定原轨迹上分支探测并找退化区间；标准答案 token 概率、强制回答采样和 yes/no 判定也属于不同观测协议。建议将 CoRD 式分数作为定位或候选排序基线，具体比较“相邻分数下降”“低绝对分数”“候选间分数差”。这些消融是本文建议，并非原论文实验。

**局限：**答案条件概率是选择信号，不能充当局部逻辑正确的证明；多教师逐步生成及 beam 会增加成本。它更直接服务完整优质轨迹构造。

### A.2 CoTEvol：在已有推理群体中做全局交叉和局部变异

**首次提交 2026-04-16，Findings of ACL 2026。** [首次版本](https://arxiv.org/abs/2604.14768) · [正式发表](https://aclanthology.org/2026.findings-acl.1903/)

同题先生成多条 CoT，以适应度挑选父代；全局交叉通过反思整合不同解法，局部变异则计算步骤平均 token 熵，保留最高不确定步骤之前的前缀，从该位置提高温度探索后续路径。迭代后选取轨迹用于 SFT。适应度包含答案、格式与长度因素，而非每步形式化验证。[方法 §3](https://arxiv.org/html/2604.14768v1)

**可借鉴点：**“改哪里”可以由不确定性决定，“改成什么”交给重新采样或解法重组。对当前项目，适合与 probe 定位进行相同预算的对照，并保留 parent→offspring 变更记录以形成局部对照数据。熵高只表示模型不确定，不保证那里有数学错误；原工作主要输出改进轨迹，不自动给出首错真值。

### A.3 SPLICE：生成过程中回退，并逐级加强提示

**论文：Splicing Hints into Reasoning Traces: Learning from Demonstrator Failures，arXiv 2610.13996；页面记录首次提交 2026-09-26。** 编号月份与提交记录不同，本文按页面实际记录标注。[日期与摘要](https://arxiv.org/abs/2610.13996) · [方法 §2](https://arxiv.org/html/2610.13996v1)

demonstrator 分块生成，持有参考解的 tutor 检查进展；停滞时回退到最近有建设性进展的段落，插入提示，再让 demonstrator 续写；反复失败则加强提示。最终保留下来的修复轨迹用于 SFT，学生在测试时不接收提示。

**与 InT 的区别：**它围绕生成中的持续进展监控和多次提示编辑构造完整轨迹，不要求只对已完成的错解做一次首错修正。适合从教师原本失败的困难证明题中挖掘训练数据。论文也分析了压缩失真、过度提示等生成缺陷；因此“有 tutor 帮助完成”不能直接等价为高质量。

**与当前项目的连接：**可以测试 probe 下降是否适合触发 tutor 干预，并与“无进展”触发比较。建议保存被截掉的失败后缀及提示强度，而非只保留最终成功文本；这是额外的数据设计建议。

### A.4 InT：在模型自身轨迹上定位并修正一步

**首次提交 2026-01-20。** [论文](https://arxiv.org/abs/2601.14209) · [官方代码](https://github.com/intervention-training/int)

参考解帮助模型在自身推理中找到关键错误，生成一步干预；无参考解续写检查能否成功，再训练 prefix + intervention。它直接提供局部修正数据，是当前项目的近邻方法。建议与 SPLICE 一起读：前者强调一步干预与信用分配，后者强调多轮生成编辑。具体 SFT 目标与过滤机制见下方背景部分及仓库 `docs/upstream.md`。

### A.5 Verifiable Counterfactual Supervision：先控制首错，再重算后续

**首次提交 2026-05-04；v3 为 2026-06-20。** 初版标题为 *Controllable and Verifiable Process Data Synthesis for Process Reward Models*，新标题为 *Verifiable Counterfactual Supervision for Process Reward Models*。[版本记录](https://arxiv.org/abs/2605.02395) · [v3 方法](https://arxiv.org/html/2605.02395v3)

先生成经过检查的正确符号链；指定中间位置，注入与局部规则匹配的错误；检查其不受前缀支持或违反结构约束；将错误结论放入新状态，重新计算后续链；最后用共享语境翻译成自然语言。这样能同时记录正确链、错误链、首错位置和错误类型。

**比单点文本改错更有用之处：**错误后的链也随状态变化，可研究错误传播。**适用边界：**主要实验在符号逻辑，数学 ProcessBench 迁移分数仍低；不能将它称作已经验证有效的高难数学数据生成方案。它更适合设计可控诊断集，或迁移到有明确规则与检查器的数学子领域。

### A.6 SCAN：针对 MC 标签噪声设计采集和学习

**首次提交 2025-09-20，NeurIPS 2025。** [论文](https://arxiv.org/abs/2509.16548) · [正式版本](https://proceedings.neurips.cc/paper_files/paper/2025/file/4dd0cfda282c778a21b38fd1d637f37b-Paper-Conference.pdf)

它关注自动续写标注中的两类噪声：弱 completer 低估正确前缀，自我纠错又会高估错误前缀。框架结合高效 MC 采集、预测错误位置附近的容忍软标签与基于置信度的重加权。[方法 §3](https://arxiv.org/html/2509.16548v1)

**可借鉴点：**低成本定位信号存在偏差时，不要直接当作硬真值。对当前项目，可在候选区间附近保留不确定标签，并依据重复探测稳定性分析质量。注意 SCAN 的具体纠偏机制针对 MC，不能未经实验直接套用到强制答案 probe。

### A.7 Rubric Rewards：将每题需要的推理证据显式化

**论文：Curing Miracle Steps in LLM Mathematical Reasoning with Rubric Rewards，首次提交 2025-10-09，ACL 2026。** [首次版本](https://arxiv.org/abs/2510.07774) · [正式论文](https://aclanthology.org/2026.acl-long.844/)

构造流程是“题目→题目专属 rubric→多模型候选解答→按 rubric 打分→按分段平衡采样”，形成 `(problem, rubric, response, score)` 训练数据。rubric 显式要求前提、关键论证与逻辑衔接，以处理答对但推导不成立的 Miracle Steps。

它提供的是按标准评价整条推理的细粒度质量信号，不能当作逐 token 或逐步首错标签。对当前项目，可把题目 rubric 转化成修正后的检查清单，检验干预是否补足所需证据，而非只使最终答案变对。rubric 还应容许不同合法解法。

### A.8 FaithSieve：细分证明义务，再用语义对齐门控形式证据

**首次提交 2026-08-26，预印本。** [论文](https://arxiv.org/abs/2608.26310)

把粗证明步骤拆成局部单元，抽取带类型的证明义务，用 Lean 辅助检查，并验证形式化陈述是否忠实保留原文的对象、条件和逻辑形式。输出通过、反驳或不确定证据，并支持首错定位。

它首先是验证与定位框架，不是完整训练数据生成器。可以将它放在合成、局部修正或反事实链之后，产生有证据的过程标签。证明失败不能直接标负；只证明同一个结论，也不一定验证了原文写出的推导方式。

## C. 针对当前项目的近期比较顺序

以下为本文实验建议，不是上述论文已经完成的组合实验。

1. **先比较位置选择：**当前 probe 翻转、CoRD 式答案条件概率变化、CoTEvol 式步骤熵、LLM 错误定位，以及随机位置。固定候选数、修正器和续写预算，区分“位置找得好”和“修正模型强”。
2. **再比较生成方式：**InT 式一步修正、保留前缀的自由分支重写、SPLICE 式分级提示。前两者适合首轮实验；多轮回退单独报告成本。
3. **给数据增加质量证据：**用 rubric 检查必要论证；选可形式化子集做局部验证；构造有已知错误位置的符号或算术对照集。
4. **同时保留三种量：**局部有效性、前缀自由续写成功率、局部替换带来的成功率差。它们支持不同任务，不能只合并成一个 correct 标签。

推荐优先深读 **CoRD → CoTEvol → SPLICE → InT**；需要做过程标签和诊断集时再看 **SCAN、反事实过程合成、FaithSieve**；需要识别“答对但没有推出来”的轨迹时看 **Rubric Rewards**。

## 背景附录：经典路线与通用数据设计

以下保留原调研的历史路线和字段建议，用于解释方法差异，不代表近期工作的阅读优先级。

## 1. 核心判断

“精细”主要体现在监督能否回答具体问题：哪一步错、为什么错、应该如何替换，以及替换后是否确实改善后续结果。增加解释长度并不自动提高监督质量。

建议区分三种信号：

| 信号 | 回答的问题 | 典型获取方式 |
| --- | --- | --- |
| 局部正确性 | 给定前提，这一步推导是否成立？ | 人工、LLM judge、符号检查、形式化证明 |
| 前缀价值 | 从当前前缀出发，指定模型多大概率最终答对？ | 多次自由续写、搜索树回报 |
| 替换效果 | 同一前缀下，把原步骤换成候选步骤，成功率变化多少？ | 原步骤与替换步骤分别分支采样 |

这三者相关，但不能互相充当真值。错误前缀可以被后续纠正，正确前缀也可能被弱模型续写失败。Qwen 的 PRM 方法研究直接分析了 MC 续写标签与步骤正确性之间的错位。[论文 §3](https://arxiv.org/html/2501.07301v2)

| 路线 | 核心构造流程 | 产物 | 成本与局限 | 代表工作 |
| --- | --- | --- | --- | --- |
| 人工过程标注 | 模型解题 → 切步 → 人工判断；可主动选择值得标注的解答 | 步骤标签、首错 | 人力高；适合校准集 | PRM800K |
| LLM 过程判定与共识过滤 | judge 定位错误 → 与续写估计对照 → 保留一致样本 | 步骤标签、首错、解释 | 中；judge 也会犯错 | Qwen PRM Lessons |
| 前缀 MC 续写 | 每个前缀多次补全 → 判最终答案 → 估计价值 | 前缀价值、代理步骤标签 | 中高；依赖续写模型 | Math-Shepherd |

## 3. 各路线具体怎么构造

### 3.1 人工标注：PRM800K

先让模型生成数学解答，再对中间步骤进行人工反馈；数据包含约 80 万个步骤级标签，不能理解为 80 万道题。其主动学习机制用于提高标注效率。适合借用标注规范，并用少量专家标注校准自动流水线，而非一开始全量人工标注。[论文](https://arxiv.org/abs/2305.20050) · [数据、格式与标注说明](https://github.com/openai/prm800k)

建议保留 `correct / incorrect / uncertain`，并明确：首错之后的步骤是“在错误前提下局部有效”，还是“相对原题已无效”。如果数据只标到首错，不应将未审查的后续步骤当作独立人工负例。

### 3.2 LLM judge + 共识过滤：Qwen PRM Lessons

该研究将 LLM 的过程判定与 MC 估计结合，保留两者对错误位置一致的样本；在一组 860K 样本的实验中约保留 40%。作者报告，这种过滤提高了过程错误识别的数据效率。该比例是特定实验结果，不是推荐固定保留率。[论文 §3.1–4](https://arxiv.org/html/2501.07301v2)

可借鉴流程：

1. 对同一轨迹独立生成 judge 判断与前缀续写统计。
2. 一致样本进入自动训练候选；分歧样本进入审查池。
3. 分歧样本按难度、题型、错误类型抽样人工复核。
4. 保存两个原始信号，而非只保存一个合并后的二值标签。

这里第 2–4 点是建议的工程设计；多种自动评估一致也不能证明结论正确，仍需独立抽检。只训练一致样本还可能偏向容易判断的错误。

### 3.3 前缀续写：Math-Shepherd

给定题目 `x` 和解题前缀 `h_i`，从这个位置采样 K 条完整续写，核验最终答案：

\[
\widehat V_\pi(h_i)=\frac{1}{K}\sum_{k=1}^{K}\mathbf 1[\mathrm{answer}(z_k)=a^*].
\]

Math-Shepherd 提供 soft estimation（成功比例）和 hard estimation（至少一次成功即为正）。它把步骤质量定义为通向正确答案的潜力，是自动构造过程监督数据的一条经典路线。[论文 §3.3](https://arxiv.org/html/2312.08935v2)

值得保存 `K`、成功数、续写模型版本和采样配置。`0/K` 只能说明这 K 次没成功；不能证明此处无法解题。若用于衡量前缀价值，尽量保留比例及不确定性；若目标是逻辑判错，应另外引入局部验证。

### 3.4 搜索式构造：OmegaPRM 与 rStar-Math

**OmegaPRM** 用分治式 MCTS 和二分定位来采集过程监督，减少朴素逐前缀检查的开销，并平衡正负样本；论文报告构造超过 150 万个过程监督标注。[论文 §3](https://arxiv.org/html/2406.06592v2)

借鉴时应区分算法的搜索效率与标签的逻辑含义：成功率受有限采样影响，且自我纠错会导致前缀价值并非单调下降，不能在所有轨迹上无条件假定存在唯一分界点。完整搜索成本也不能仅用二分的查询轮数衡量。

**rStar-Math** 将一步自然语言推理与 Python 代码共同生成，用代码执行过滤候选，并在搜索中累计 Q 值，再构造步骤偏好来训练过程偏好模型。适合一次采集同时服务 SFT 与步骤排序。[论文 §3](https://arxiv.org/html/2501.04519v1) · [作者仓库](https://github.com/microsoft/rStar)

代码成功运行只说明程序可执行；是否忠实表达题意、是否满足数学前提，仍需检查。搜索 Q 值也属于回报估计，不是数学证明。

### 3.5 同前缀的步骤偏好：Step-DPO

构造的是 `(问题, 前缀, 好的下一步, 坏的下一步)`。作者先采集模型错解，由人工或 GPT-4 找首错；从首错之前的前缀用原模型重新采样，筛出最终答对的续写，取其第一步作为正例，并进一步检查正例步骤本身。论文构造了 10K 步骤偏好对。[论文 §3.2](https://arxiv.org/html/2406.18629v1) · [代码与数据](https://github.com/JIA-Lab-research/Step-DPO)

这一设计的价值是固定上下文，监督集中在分叉位置。实际构造时需要确保：两个候选都能衔接原前缀；chosen 本身有效；差异不只是长度、语气或答案泄漏。原模型能生成的正例与 teacher 直接重写的正例，可作为分布差异的消融。

### 3.6 一步干预：InT

模型先生成轨迹，再借助参考解定位关键错误并提出一条干预；学生仅在原问题、保留前缀与干预之后续写。该工作比较不同 SFT 目标，推荐配置是克隆 prefix + intervention、排除 suffix，并用成功续写过滤。这个结论来自其具体实验，不能推广为所有数学 SFT 都应删掉 suffix。[论文 §3–4](https://arxiv.org/html/2601.14209v1) · [官方实现](https://github.com/intervention-training/int)

与完整正确解相比，这种数据提供了一个局部“补丁”。但成功补丁不等于严格首错标注：提前引导策略也可能提高成功率。应分别记录定位依据、修改内容与续写效果。

### 3.7 自我纠错轨迹：RISE 与 SCoRe

**RISE** 把单次解题扩展成多轮过程，通过迭代采集和训练，让模型根据之前失败的尝试改变解法。[论文](https://arxiv.org/abs/2407.18219) · [官方代码](https://github.com/cmu-mind/RISE)

**SCoRe** 使用模型自身生成的多轮轨迹进行在线 RL，指出离线纠错 SFT 可能受到错误分布不匹配和行为坍缩影响。[论文](https://arxiv.org/abs/2409.12917)

若研究目标是回溯和自我纠错，数据应真实保留“原尝试、反馈、修正尝试”及每轮结果。只从正确解扩写几句“等等，我错了”，缺少对应的失败状态与实际修正证据。评估还要同时观察 wrong→right 和 right→wrong，避免只学会无条件改答案。

### 3.8 受控错误注入：PRMBench

PRMBench 从 PRM800K 的可靠解法出发，用类别化提示修改题目或推理过程，再人工审核；覆盖冗余、循环论证、前提缺失、步骤矛盾等维度，共 6,216 个测试案例、83,456 个步骤标签。它主要是评测集，可借用构造思路，不能直接混入训练后仍用同一测试集评估。[论文 §3.2–3.3](https://arxiv.org/html/2501.03124v2) · [官方仓库](https://github.com/ssmisya/PRMBench)

可以在新的训练题目上构造以下对照：

| 修改类型 | 示例 | 可研究的问题 |
| --- | --- | --- |
| 算术/符号错误 | 将 `3×7=21` 改为 `24` | 是否能检测局部计算错误 |
| 前提缺失 | 在未证非零时约分；平方后漏验根 | 是否检查适用条件 |
| 推理错误 | 将必要条件当充分条件 | 是否理解逻辑方向 |
| 中性修改 | 等价改写、变量重命名、格式变化 | 是否被表面形式误导 |
| 正确替换 | 同一前缀下换成另一条合法推导 | 是否容忍多解法 |

这些是建议的操作类别。注入位置只是“修改发生的位置”；原解法若本身有问题，或改动引入了多个后果，不能自动当成首错真值。每次修改都应重新审核。

### 3.9 从符号系统生成，或用形式系统验证

**AlphaGeometry：先生成可验证结构，再提取题目与证明。** 从随机几何前提出发，以符号推导和回溯抽取定理、证明与辅助构造训练样本，构造约 1 亿条合成定理与证明。优势是推导来源可追溯，适合几何专用语言；覆盖受推导规则和表示语言限制。[Nature 原论文](https://www.nature.com/articles/s41586-023-06747-5)

**TP-as-a-Judge：生成推理后转成形式化检查。** 通过迭代自动形式化，用 Lean 反馈评估中间推理；适合已有自然语言数学数据的质量过滤。[论文](https://arxiv.org/abs/2502.13137)

**FaithSieve：检查更局部的证明义务。** 这篇 2026 年 8 月预印本将粗步骤拆成局部单元，抽取带类型的证明义务，用语义对齐门控决定是否采用 Lean 证据。可借鉴“拆分—对齐—验证—融合”的设计，但本文未复现其效果。[论文](https://arxiv.org/html/2608.26310v1)

形式化路线尤其需要保留 `verified / refuted / unknown`。证明器超时或搜索失败不等于命题错误；形式化命题被证明，也还需要核验它是否忠实对应原自然语言步骤。若验证器直接从原题重新求出了结论，未必验证了学生写出的那条推导。

## 4. 完整轨迹数据怎么用

完整正确轨迹仍然适合作为基础 SFT 和种子。OpenMathInstruct-2 通过解法扩增与问题扩增构建约 14M 问答对，研究了教师能力、解法格式、题目多样性与过滤策略；其结果也提醒，过于冗长的解法不一定更利于 SFT。[论文](https://arxiv.org/abs/2410.01560)

建议把它与细粒度数据分工使用：完整轨迹覆盖知识与解题策略；局部标签训练判错；偏好对训练下一步选择；修正对训练干预与纠错。不要因为最终答案核验通过，就把完整链中每一步自动标为逻辑正确。

## 5. 对当前 probe_intervention 项目的建议

本节依据当前仓库 README 与 docs/upstream.md 的方法描述提出建议，不代表已检查实际模型行为或完成实验。

### 5.1 先明确 probe 在测什么

当前 answer probe 在前缀处关闭 think 并强制直接回答，其观测量可写成：

\[
P_{\mathrm{probe}}(h_i)=P(\text{强制答案正确}\mid x,h_i,\text{probe template}).
\]

它与自由续写的 `V_pi(h_i)` 不是同一个协议。若使用包含标准答案的 yes/no judge 模式，它又属于另一类信号。建议分别保存，不能统称为同一个“步骤正确概率”。

相邻 correct→wrong 翻转适合作为候选定位器。它是否对应逻辑首错，需要独立人工或局部验证；它是否对应可修复的瓶颈，需要替换后的分支结果。

### 5.2 更有信息量的数据单元

建议主数据单元是“原始轨迹上的一个位置及其候选分支”，而非只保存过滤后的成功轨迹：

```text
题目 x + 固定前缀 h
  ├─ 原步骤 s0   → K 次自由续写 → c0 次成功
  ├─ 修正步骤 s1 → K 次自由续写 → c1 次成功
  └─ 中性改写 sn → K 次自由续写 → cn 次成功

另存：局部逻辑标签、错误类型、probe 输出、定位来源、验证证据
```

在同一续写模型、采样协议与预算下，估计：

\[
\widehat\Delta(h;s_1,s_0)=\widehat V_\pi(h\oplus s_1)-\widehat V_\pi(h\oplus s_0).
\]

该量描述具体替换在指定续写协议下的效果。它不能单独证明原步骤是首错；如果修正同时加入新知识、改变策略和增加 token，也不能将效果归因于单一错误机制。中性改写与局部修改审查有助于解释结果。

### 5.3 建议的首轮实验

以下规模与参数是起步建议，不是文献确认的最优配置。

1. 从训练集选取 300–500 题，按代数、数论、组合/概率及难度分层。评估题单独固定，并让同题的所有分支保持在同一 split。
2. 每题采样 2–4 条原始轨迹；保留最终正确与错误两类，因为答对轨迹也可能有局部缺陷。
3. 用相同轨迹与候选位置预算比较：probe 翻转、LLM 首错定位、自由续写价值下降、随机位置。零候选也计入覆盖率。
4. 固定局部 teacher 提示、参考信息与修正预算，先隔离定位器差异；后续再比较修正生成方法。
5. 对原步骤、修正步骤和中性改写分别续写。先用 K=4 粗筛，分歧或高价值位置增加到 K=16–32；自适应选出的效果应再用独立续写复核，避免筛选偏差。
6. 对候选位置和非候选位置都抽样人工标注；评估局部错误精度、召回与可修复率。若只标候选，无法估计漏掉多少错误。
7. 导出步骤偏好、prefix+intervention、完整成功轨迹三种训练视图；比较时报告题目数、轨迹数、训练 token 和生成/验证成本。

### 5.4 需要报告的指标

| 层面 | 指标 |
| --- | --- |
| 定位 | 候选覆盖率、首错位置准确率；粗 token 区间用独立的区间命中率 |
| 局部质量 | 步骤正确率、首错判定精度、unknown 比例、错误类型分布 |
| 干预 | 原始与修正的续写成功率、成功率差、不确定性、中性改写效果 |
| 纠错 | wrong→right、right→wrong；保持原正确答案的能力 |
| 数据效率 | 每千题/每百万生成 token 得到的有效局部样本数 |
| 下游训练 | 固定题目集与推理预算的 pass@1；多采样指标同时报告预算 |

不能只报告“至少一次成功的干预比例”，因为它随续写次数增加自然升高。也不能用与筛选相同的一组续写无偏地估计最终干预效果。

## 7. 历史方法索引与评测资源

以下是历史路线的索引；近期阅读顺序以本文 C 节为准：

1. [Step-DPO](https://arxiv.org/abs/2406.18629)：局部偏好数据的直接构造流程。
2. [InT](https://arxiv.org/abs/2601.14209)：局部修正、续写过滤与 SFT 目标。
3. [PRM Lessons](https://arxiv.org/abs/2501.07301)：MC 标签与逻辑正确性错位、共识过滤。
4. [OmegaPRM](https://arxiv.org/abs/2406.06592)：减少过程数据采集成本的搜索设计。
5. [PRMBench](https://arxiv.org/abs/2501.03124)：类型化扰动与细粒度验证能力。

独立评测可参考：

- [ProcessBench](https://arxiv.org/abs/2412.06559)：3,400 个专家标注案例，任务是找最早错误或判断全对，适合步骤定位评估。
- [ProofBench / ProofGrader](https://arxiv.org/abs/2510.13888)：145 道题、435 份模型证明及专家评分。其“细粒度”主要是 0–7 分证明评分，不应误认为每个步骤都有对错标签。
- [FaithSieve / ProofLoc](https://arxiv.org/abs/2608.26310)：局部证明义务及首错定位，适合进一步关注证明题的研究。

本调研的实施建议是：先用少量可靠标注校准定位信号，再构造“同前缀、局部替换、多次续写、有独立验证”的分支数据。它能同时支持过程判别、偏好学习与干预训练，也能更清楚地区分逻辑正确性、答案可恢复性与修正效果。
